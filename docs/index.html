Keep your dev Mac fast. Keep the headroom.

Headroom is a small menu bar app that shows what's filling your disk and memory while you run simulators, emulators, dev servers and agent sessions. It cleans rebuildable developer caches, but only after you've seen exactly what goes and clicked to confirm.

Everything a busy dev Mac needs to watch

Live health for the moment, storage for the long run, and an honest report of what can be reclaimed.

Live health

Memory pressure, swap, CPU, thermal state and free disk, with an hour of charts and a menu bar icon that turns into a warning when something needs you.

Grouped by what you run

Memory and CPU per iOS Simulator, Android emulator, Claude Code agent (one row per worktree), Metro, Next.js, Nx, Gradle, Xcode, Docker and browsers.

Storage you can trust

Sizes of 20 known developer caches, from DerivedData and DeviceSupport to Gradle, npm, Yarn, pnpm, CocoaPods and Metro, against a free-space target.

Review, then confirm

Every clean-up shows what goes, how big it is and how it rebuilds. Dry run is on until you turn it off. Caches whose tool is running are skipped.

Simulators and devices

Simulator runtimes and devices, Android AVDs and system images, and Xcode archives, with size and last use. Each one needs its own confirmation.

Worktree report

Every git worktree under ~/Developer with branch, uncommitted changes, unpushed commits and node_modules size. Read-only, so you decide.

Workload snapshots

Record "1 sim + 1 emu + Metro + Next + 2 agents" and keep its peaks: memory, pressure, swap growth, CPU and heat. Know what your Mac can carry.

History and undo notes

Every action is logged locally: what, when, how big, and how to undo it. Export it as Markdown whenever you like.

A CLI too

headroom-cli prints the same reports in your terminal: health, processes, storage, devices, worktrees and a dry-run plan.

Made for the way you actually develop

Headroom knows the tools that fill a mobile and web developer's Mac, and it groups them the way you think about them: by device, by dev server, by agent session and by project folder.

Command lines are read only to recognise a process. They're never stored or shown.

Careful by design

A clean-up tool should never be the thing that costs you work. These rules are enforced in code and covered by tests.

  • Nothing is deleted without your clickAnd nothing is ever deleted automatically or on a schedule.
  • Only allow-listed cachesEach target is checked when the plan is made and again right before removal. No .., no symlink tricks.
  • Your work is off limitsNever inside a git working tree, never a .env*.local file, and repositories are read-only.
  • Bigger things, one at a timeSimulators go through xcrun simctl. AVDs, images and archives go to the Trash so you can put them back.
  • Logs stay closedLogs, env files and configs are shown by size and location only. They may hold private data.
  • No network, no telemetry, no sudoIt never phones home and never touches SIP, Gatekeeper, FileVault, the firewall or updates.

Get started in a minute

Download the app, or build it yourself with the Xcode you already have.

  1. Download Headroom.zip, unzip it and move Headroom to Applications.
  2. Open it. The first time, macOS blocks it because it isn't notarized yet: click Done, then System Settings ▸ Privacy & Security ▸ Open Anyway. Details
  3. The icon appears in your menu bar. Scan storage, review a dry run, and decide.
